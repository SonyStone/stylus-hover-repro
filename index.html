Chrome Android: stylus hover stops after file chooser / PWA switch

Stylus hover: not received yet — hover the pen over the gray area

Hover the stylus here without touching. Blue circle = hover, red = contact.

Event log (window, capture phase)

Steps to reproduce

A. File chooser

  1. Open this page in Chrome on an Android tablet with a hovering stylus (EMR / USI).
  2. Hover the stylus over the gray area without touching. The indicator turns green ("receiving"), the blue circle follows the pen.
  3. Tap "open the file chooser" and cancel the picker (picking a file has the same effect).
  4. Hover the stylus again.

B. Installed app (PWA)

  1. Chrome menu → Add to home screen → Install. Open the installed app and hover: hover is never received.
  2. Alternatively, with the app installed, switch between the installed app and this page in a Chrome tab: hover stops in the tab too.

Expected: pointermove events with pointerType=pen, buttons=0 keep arriving while the pen hovers.

Actual: hover events stop for good in this tab. The pen appears only on contact: pointerover + pointerdown in the same millisecond, and pointerout + pointerleave with relatedTarget=null on every lift. Each contact gets a new pointerId. The element that was under the pen stays in :hover (yellow button). Reload, fullscreen, switching tabs and rotation do not help; only a new tab does. Switching apps through the Recents screen does not trigger it. Android itself still delivers hover (getevent shows ABS_DISTANCE, dumpsys input lists the Chrome window in hoveringPointers).
